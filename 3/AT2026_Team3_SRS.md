# 1. Введение
[Обзор всего документа SRS.]

## Цели
Целью разрабатываемой системы является автоматизация и наведение порядка в деятельности по заключению различных договоров (включая приходные и расходные) на предприятии. 
Внедрение системы предназначено для обеспечения проведения согласования договоров в строгом соответствии с установленным регламентом, сокращения времени, затрачиваемого на работу с договорами и прозрачности процесса электронного документооборота.

## Границы применения
Разрабатываемое ПО является корпоративной системой для автоматизации процесса заключения договоров на предприятии.

Система предназначена для регламентирования и сокращения времени заключения договоров, а также для оптимизации хозяйственной деятельности предприятия. Способна работать с приходными и расходными документами.

Система охватывает следующие основные этапы процесса:
* Инициирование заключения договора сотрудником предприятия.
* Загрузка текста договора в систему.
* Формирование маршрута согласования.
* Выбор вида согласования.
* Прохождение договором маршрута согласования.
* Обработка результатов, полученных на этапе прохождения маршрута согласования.
* Возврат договора инициатору после первого отказа (вместе с обязательным комментарием).
* Возможность повторного согласования для изменённого договора.
* Учёт количества кругов согласования.

Система должна взаимодействовать с кадровой базой предприятия для получения сведений о сотрудниках, участвующих в согласовании.

Система автоматизирует установленный по регламенту процесс согласования документов, но не определяет регламент.

Система не предусматривает участие в процессе согласования внешних по отношению к предприятию лиц.

Система не предусматривает никаких видов согласования, за исключением параллельного и последовательного.


## Термины и аббревиатуры
| **Термин/Аббревиатура** | **Определение** |
| --- | --- |
| Договор | Документ, заключение которого регламентировано на предприятии и подлежит согласованию в соответствии с установленным порядком. В системе классифицируются на приходные и расходные. |
| Инициатор | Сотрудник предприятия, который инициирует процесс заключения договора: загружает текст, выбирает вид и маршрут согласования, обрабатывает замечания при несогласовании. |
| Согласующий | Сотрудник предприятия, включенный в маршрут согласования. Изучает документ и выносит вердикт. |
| Маршрут согласования | Упорядоченный список сотрудников предприятия, которые должны обработать документ. |
| Круг согласования | Один полный цикл прохождения документа по маршруту согласования. |
| Последовательное согласование | Вид согласования, при котором каждый следующий согласующий получает документ только после обработки предыдущим. |
| Параллельное согласование | Вид согласования, при котором все согласующие получают документ одновременно. |
| Вердикт | Решение согласующего по документу. Принимает два значения: «согласовано» (комментарий не обязателен) или «не согласовано» (комментарий обязателен). |
| Согласованный договор | Договор, получивший вердикт «согласовано» от всех участников маршрута. |
| Несогласование | Ситуация, при которой хотя бы один участник вынес вердикт «не согласовано». Текущий круг завершается, документ снимается с остальных участников и возвращается инициатору. |
| Регламент | Установленный на предприятии порядок заключения договоров, которому должна строго соответствовать работа системы. |
| Кадровая база | Внешняя информационная система предприятия с данными о сотрудниках. Система периодически получает из неё сведения о сотрудниках для формирования маршрутов согласования. |
| СТПО | Спецификация требований к программному обеспечению. Настоящий документ. |
| API | Программный интерфейс для обмена данными между системами. Используется для интеграции системы с кадровой базой. |
| Учётная запись | Запись в системе, идентифицирующая сотрудника и позволяющая ему войти в систему под своим именем. |
| Администратор системы | Сотрудник, отвечающий за настройку системы, управление учётными записями и сопровождение. |

# 2. Общее описание

## Описание изделия
Разрабатываемое ПО представляет собой корпоративную систему автоматизации согласования договоров. 

* **Интерфейсы системы**: подлежат выяснению.
* **Интерфейсы пользователя**: Система должна предоставлять интерфейс, позволяющий инициаторам создавать текст договора в соответствии с требованиями и набирать маршрут согласования, а согласующим — изучать документ и выносить вердикты.
* **Интерфейсы аппаратных средств ЭВМ**: подлежат выяснению.
* **Интерфейсы программного обеспечения**: Система должна обеспечивать периодическое получение сведений о сотрудниках из кадровой базы предприятия для формирования маршрутов согласования.
* **Интерфейсы коммуникаций**: подлежат выяснению.
* **Ограничения памяти**: подлежат выяснению.
* **Действия**: 
  * Создание/загрузка текста договора в систему инициатором.
  * Формирование маршрута согласования из сотрудников предприятия.
  * Маршрутизация документа по параллельному или последовательному виду согласования, выбранному инициатором.
  * Сбор вердиктов («согласовано», «не согласовано») и комментариев (обязательных при вердикте «не согласовано») от сотрудников.
  * Автоматическое снятие документа с рассмотрения у остальных участников и возврат инициатору при первом отказе (вердикте «не согласовано») в цепочке.
  * Отслеживание и учет количества пройденных кругов согласования для каждого документа.

## Функции изделия
Основными функциями изделия являются:

* Управление процессом заключения договоров.
* Загрузка договоров инициатором.
* Формирование маршрута из сотрудников предприятия для согласования договора.
* Выбор вида согласования.
* Передача договора участникам маршрута в соответствии с выбранным видом согласования.
* Рассмотрение договора участниками с последующим вынесением вердиктов «согласовано» или «не согласовано».
* Добавление комментариев к результатам согласования.
* Обработка несогласования договора.
* Уведомление инициатора о результатах согласования.
* Возврат договора инициатору при вердикте «не согласовано» для внесения изменений.
* Внесение изменений в договор.
* Возможность повторного запуска процесса согласования договоров.
* Учёт количества кругов согласования по каждому договору.
* Получение сведений о сотрудниках предприятия из кадровой базы.

## Характеристики пользователей
Система автоматизации процесса заключения договоров предназначена для использования сотрудниками предприятия, участвующими в подготовке, согласовании и учёте договоров. Все пользователи системы делятся на три основные категории в зависимости от выполняемых функций и роли в процессе заключения договора:
| Пользователь | Функции и ответственность |
|---|---|
| Инициатор | Сотрудник, желающий заключить договор (приходный или расходный). Входит в систему, загружает текст договора, выбирает вид согласования (последовательное/параллельное), указывает маршрут из сотрудников. Получает сообщение о несогласовании, правит документ и отправляет на новый круг. |
| Согласующий | Сотрудник, включённый в маршрут согласования. Получает договор, изучает и выносит вердикт «согласовано»/«не согласовано». При несогласовании обязан оставлять комментарий. |
| Администратор системы | Отвечает за настройку, сопровождение и работоспособность системы. Управляет учётными записями, настраивает правила формирования маршрутов и доступные виды согласования, обеспечивает получение данных из кадровой базы, контролирует работу системы, просматривает журналы, решает инциденты. |


## Ограничения
В данном подразделе приводится общее описание факторов, ограничивающих выбор разработчика. Ограничения сформулированы на основе исходного описания концепции системы.

**Ограничения по видам согласования**
- Система поддерживает только два вида согласования: последовательное и параллельное. Иные виды согласования в рамках данной концепции не рассматриваются.

**Ограничения по выбору вида и маршрута согласования**
- Выбор вида согласования возлагается на инициатора; иные способы выбора не рассматриваются.
- Маршрут согласования формируется инициатором; иные способы формирования маршрута не рассматриваются.
- Маршрут согласования формируется только из сотрудников предприятия; внешние участники не рассматриваются.
- Система зависит от данных кадровой базы для формирования маршрутов согласования.

**Ограничения по вердиктам согласующих**
- Согласующий может вынести только два вердикта: «согласовано» или «не согласовано».
- При вердикте «не согласовано» комментарий обязателен.
- При вердикте «согласовано» комментарий может быть добавлен, но не является обязательным.

**Ограничения по условию согласования договора**
- Договор считается согласованным только в том случае, если его согласовали все участники маршрута.

**Ограничения по обработке несогласования**
- Если хотя бы один участник вынес вердикт «не согласовано», текущий круг согласования завершается в этот момент.
- Документ снимается с согласования у остальных участников, даже если они не успели его обработать.
- После несогласования инициатор получает сообщение, изменяет документ и отправляет его на следующий круг согласования.

**Ограничения по учёту**
- Количество кругов согласования по каждому документу отслеживается системой.

**Ограничения по времени на шаг согласования**
- Система должна поддерживать параметр «максимальное время на шаг» согласования. По истечении этого времени дальнейшее поведение системы подлежит уточнению.

## Предположения и зависимости
Настоящий подраздел фиксирует факторы, которые не являются требованиями к системе, но влияют на них. Изменение любого из перечисленных ниже предположений или зависимостей может потребовать пересмотра требований, изложенных в разделе 3.

### Предположения

**Наличие кадровой базы.**
Предполагается, что на предприятии существует кадровая база, содержащая актуальные данные о сотрудниках: ФИО, должность, подразделение, статус (работает/уволен). Система автоматизации согласования договоров использует эти данные для формирования маршрутов согласования.

**Способ получения данных.**
Предполагается, что кадровая база предоставляет способ периодического получения сведений о сотрудниках (программный интерфейс, выгрузка, синхронизация). Конкретный способ определяется на этапе проектирования.

**Наличие регламента согласования.**
Предполагается, что на предприятии существует утверждённый регламент согласования договоров. Система автоматизирует этот регламент, но не заменяет его.

**Электронная форма договора.**
Предполагается, что текст договора, загружаемый инициатором в систему, представлен в электронной форме в виде файла. Система не выполняет распознавание сканированных бумажных документов.

**Наличие учётных записей.**
Предполагается, что все сотрудники, участвующие в согласовании договоров (инициаторы и согласующие), зарегистрированы в системе и имеют учётные записи. Создание учётных записей выполняется администратором системы.

**Квалификация пользователей.**
Предполагается, что пользователи системы обладают базовыми навыками работы с компьютером и веб-браузером. Система не предназначена для пользователей без опыта работы с компьютером.

### Зависимости

**Зависимость от кадровой базы.** 
Функционирование системы в части формирования маршрутов согласования зависит от доступности и корректности данных кадровой базы. При изменении структуры или формата данных кадровой базы потребуется доработка модуля получения данных.

**Зависимость от регламента согласования.**
При изменении регламента согласования договоров на предприятии (например, изменении правил формирования маршрутов согласования или порядка вынесения вердиктов) может потребоваться изменение требований к системе.

**Зависимость от законодательства.**
Требования к хранению, обработке и защите персональных данных сотрудников, используемых в системе, зависят от действующего законодательства. При изменении законодательства требования к системе могут быть пересмотрены.

**Зависимость от инфраструктуры.**
Работа системы зависит от наличия локальной вычислительной сети и серверного оборудования. Конкретные требования к инфраструктуре определяются на этапе проектирования.

# 3. Детальные требования

## Функциональные требования

### 1. Пользователи и интеграция (Управление пользователями)

**R1.01.01 Взаимодействие с внешней кадровой базой**
* **Группа:** Пользователи и интеграция

### 3. Управление маршрутизацией (Инициация согласования)

**R1.03.01 Установка максимального времени на шаг согласования**
* **Группа:** Управление маршрутизацией
* **Описание:** В системе должен быть предусмотрен параметр «максимальное время на шаг», ограничивающий время обработки документа одним согласующим.

* **Ссылается на:** -

**R1.03.02 Выбор маршрута согласования**
* **Группа:** Управление маршрутизацией
* **Описание:** Система должна позволять Инициатору набирать маршрут согласования. Инициатор должен самостоятельно указывать сотрудников из внешней кадровой базы, которые будут участвовать в согласовании.
* **Приоритет:** 1
* **Ссылается на:** R1.01.01

**R1.03.03 Выбор вида согласования**
* **Группа:** Управление маршрутизацией
* **Описание:** Инициатор должен иметь возможность выбрать вид согласования при инициации документа: последовательное или параллельное.
* **Приоритет:** 1
* **Ссылается на:** R1.03.04; R1.03.05

**R1.03.04 Последовательное согласование**
* **Группа:** Управление маршрутизацией
* **Описание:** При выборе последовательного согласования система должна направлять документ каждому следующему согласующему в цепочке исключительно после того, как предыдущий сотрудник завершил его обработку.
* **Приоритет:** 1
* **Ссылается на:** R1.03.03

**R1.03.05 Параллельное согласование**
* **Группа:** Управление маршрутизацией
* **Описание:** При выборе параллельного согласования система должна направлять документ сразу всем сотрудникам, включенным в маршрут согласования.
* **Приоритет:** 1
* **Ссылается на:** R1.03.03

### 4. Управление согласованием (Обработка вердиктов)

**R1.04.01 Положительный вердикт**
* **Группа:** Управление согласованием
* **Описание:** Согласующий должен иметь возможность выбрать вердикт «согласовано». В этом случае система должна позволять (но не требовать) добавить к вердикту текстовый комментарий (например, для указания на опечатки).
* **Приоритет:** 1
* **Ссылается на:** -

**R1.04.02 Отрицательный вердикт**
* **Группа:** Управление согласованием
* **Описание:** Согласующий должен иметь возможность выбрать вердикт «не согласовано». При выборе этого вердикта система должна требовать от пользователя обязательного ввода текстового комментария в свободной форме (без предустановленных вариантов причин).
* **Приоритет:** 1
* **Ссылается на:** -

**R1.04.03 Прерывание круга согласования**
* **Группа:** Управление согласованием
* **Описание:** Если хотя бы один из участников выносит вердикт «не согласовано», система должна немедленно завершить текущий круг согласования. При этом документ должен автоматически сниматься с рассмотрения у остальных участников маршрута, даже если они еще не успели его обработать.
* **Приоритет:** 1
* **Ссылается на:** R1.04.02

**R1.04.04 Уведомление об отказе**
* **Группа:** Управление согласованием
* **Описание:** При получении вердикта «не согласовано» система должна отправить инициатору соответствующее сообщение с комментарием, указанным согласующим при вынесении вердикта «не согласовано».
* **Приоритет:** 1
* **Ссылается на:** R1.04.02

**R1.04.05 Инициация нового круга**
* **Группа:** Управление согласованием
* **Описание:** После отклонения документа система должна предоставлять инициатору возможность внести изменения в договор (загрузить обновленный файл) и запустить его на следующий круг согласования.
* **Приоритет:** 1
* **Ссылается на:** R1.02.01; R1.04.04

**R1.04.06 Успешное завершение согласования**
* **Группа:** Управление согласованием
* **Описание:** Система должна устанавливать статус документа как окончательно согласованный только в том случае, если вердикт «согласовано» вынесли все участники маршрута согласования.
* **Приоритет:** 1
* **Ссылается на:** R1.04.01

### 5. Учет и отчетность

**R1.05.01 Отслеживание кругов согласования**
* **Группа:** Учет и отчетность
* **Описание:** Система должна вести автоматический учет количества кругов согласования по каждому документу, а также сохранять комментарии, сопровождавшие вердикты «не согласовано».
* **Приоритет:** 2
* **Ссылается на:** R1.04.05

* **Группа:** Надёжность\Отказоустойчивость

**R2.04.01 Точность**
* **Группа:** Надёжность\Целостность данных
* **Описание:** Система должна обеспечивать корректное сохранение и отображение файлов договоров, маршрутов согласования, вердиктов, комментариев и сведений о количестве кругов согласования. Результаты согласования должны соответствовать решениям участников маршрута. * **Описание:** Не допускаются ошибки, приводящие к потере или искажению сохранённых данных, ошибочному завершению согласования либо установлению статуса окончательно согласованного договора без положительных вердиктов всех участников маршрута. Допустимое количество прочих ошибок и период их подсчёта подлежат согласованию с заказчиком.
* **Приоритет:** 1
* **Ссылается на:** R2.04.01

**R2.06.01 Сохранение целостности при сбое**
* **Группа:** Надёжность\Восстановление
* **Описание:** При возникновении сбоя система должна сохранять целостность ранее записанных данных. Восстановление работоспособности не должно приводить к потере зарегистрированных решений участников, нарушению последовательности согласования или некорректному изменению статуса договора.
* **Приоритет:** 1
* **Ссылается на:** R2.04.01

**R2.07.01 Устойчивость к недоступности кадровой базы**
* **Группа:** Надёжность\Внешние зависимости
* **Описание:** Временная недоступность внешней кадровой базы не должна приводить к потере уже сохранённых договоров и результатов согласования. Получение сведений о сотрудниках должно возобновляться после восстановления доступности кадровой базы в соответствии с установленным периодом обмена данными.

* **Ссылается на:** R1.01.01

## Производительность
Все указанные в разделе величины подлежат уточнению.

### 1. Время отклика

**R3.01.01 Время отклика при работе с договором**
- **Группа:** Производительность \ Время отклика
- **Описание:** При открытии договора инициатором или согласующим система должна отображать текст документа не позднее чем через **3 секунды** для 95 % запросов при нормальной рабочей нагрузке (до 50 одновременных пользователей).
- **Приоритет:** 1
- **Ссылается на:** R3.02.01

**R3.01.02 Время фиксации вердикта**
- **Группа:** Производительность \ Время отклика
- **Описание:** После нажатия согласующим кнопки «Согласовано» или «Не согласовано» система должна зафиксировать вердикт и обновить статус договора не позднее чем через **2 секунды** для 95 % запросов.
- **Приоритет:** 1
- **Ссылается на:** R3.01.01

**R3.01.03 Время уведомления участников**
- **Группа:** Производительность \ Время отклика
- **Описание:** После отправки договора инициатором на согласование система должна уведомить всех участников маршрута не позднее чем через **5 секунд** при последовательном виде и **10 секунд** при параллельном виде (при маршруте до 20 участников).
- **Приоритет:** 1
- **Ссылается на:** —

### 2. Пропускная способность и нагрузка

**R3.02.01 Пропускная способность**
- **Группа:** Производительность \ Пропускная способность
- **Описание:** Система должна обеспечивать обработку не менее **100 договоров в час** в режиме нормальной нагрузки и не менее **300 договоров в час** в режиме пиковой нагрузки без превышения времени отклика, указанного в R3.01.01–R3.01.03.

**R3.02.02 Одновременные пользователи**
- **Группа:** Производительность \ Нагрузка системы
- **Описание:** Система должна поддерживать одновременную работу не менее **200 пользователей**, из которых не менее **50** могут одновременно находиться в процессе согласования договоров. При превышении этого порога система должна выдавать предупреждение администратору.
- **Приоритет:** 1
- **Ссылается на:** R3.01.01

**R3.02.03 Объём обрабатываемых договоров**
- **Группа:** Производительность \ Нагрузка системы
- **Описание:** Система должна обеспечивать хранение и обработку не менее **10 000 договоров в год** без деградации времени отклика, указанного в R3.01.01–R3.01.03.
- **Приоритет:** 2
- **Ссылается на:** R3.02.02

### 3. Утилизация ресурсов

**R3.03.01 Потребление ресурсов сервером**
- **Группа:** Производительность \ Утилизация ресурсов
- **Описание:** При нормальной рабочей нагрузке (до 50 одновременных пользователей) серверная часть системы должна потреблять не более **70 % CPU** и не более **4 ГБ оперативной памяти**. При пиковой нагрузке допускается кратковременное потребление до **90 % CPU**.
- **Приоритет:** 2
- **Ссылается на:** R3.02.02

**R3.03.02 Подсчёт кругов согласования**
- **Группа:** Производительность \ Утилизация ресурсов
- **Описание:** Операция подсчёта и отображения количества кругов согласования по договору должна выполняться не позднее чем через **1 секунду** после запроса, независимо от числа кругов (до 100).
- **Приоритет:** 3
- **Ссылается на:** —

### 4. Масштабируемость и интеграция

**R3.04.01 Масштабируемость**
- **Группа:** Производительность \ Масштабируемость

## Ограничения проекта

**R5.01.01 Ограничения по интеграции с кадровой базой**
* **Группа:** Ограничения проекта\Интеграция
* **Описание:** Система должна обеспечивать периодическое получение сведений о сотрудниках из кадровой базы предприятия. Кадровая база является внешней системой и не разрабатывается в рамках данного проекта. Изменение структуры или формата данных кадровой базы требует доработки модуля получения данных.
* **Приоритет:** 1
* **Ссылается на:** R1.01.01

**R5.02.01 Ограничения по форме договора**
* **Группа:** Ограничения проекта\Форма договора
* **Описание:** Договор поступает в систему в виде загружаемого файла. Система не проверяет соответствие договора шаблонам и не выполняет распознавание сканированных бумажных документов.
* **Приоритет:** 1
* **Ссылается на:** R1.02.01

**R5.03.01 Ограничения по процессу согласования**
* **Группа:** Ограничения проекта\Процесс согласования
* **Описание:** Система поддерживает только два вида согласования: последовательное и параллельное. Выбор вида согласования и формирование маршрута выполняются инициатором. Маршрут формируется только из сотрудников предприятия. Согласующий выносит только два вердикта: «согласовано» или «не согласовано». Договор считается согласованным только при согласовании всеми участниками маршрута. При первом вердикте «не согласовано» текущий круг завершается, документ снимается с остальных участников и возвращается инициатору. Система должна поддерживать параметр «максимальное время на шаг» согласования.
* **Приоритет:** 1
* **Ссылается на:** R1.03.01–R1.04.06

**R5.04.01 Ограничения по учёту**
* **Группа:** Ограничения проекта\Учёт
* **Описание:** Система должна отслеживать количество кругов согласования по каждому документу.
