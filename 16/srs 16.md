# 1. Введение
Цель документа - зафиксировать требования к информационной системе проката электросамокатов, обеспечивающей управление парком самокатов, регистрацию пользователей, оформление и завершение аренды, контроль местоположения самокатов, блокировку и разблокировку самокатов, а также расчёт стоимости использования.

Особенностью системы является использование аппаратного модуля определения местоположения самоката. Для снижения затрат модуль не передаёт координаты непрерывно, а осуществляет обмен данными с системой посредством SMS-сообщений по запросу серверного центра. Полученные координаты используются системой для определения местоположения самоката и проверки нахождения в разрешённой зоне завершения аренды.

## Цели
Основными целями системы являются:

- предоставление пользователю возможности зарегистрироваться в системе и управлять арендой через мобильное приложение;
- предоставление возможности идентифицировать самокат посредством QR-кода;
- автоматическое разблокирование самоката после оформления аренды;
- автоматическое блокирование самоката после завершения аренды;
- контроль местоположения самокатов с использованием GPS и SMS-сообщений по инициативе центра;
- определение нахождения самоката в специальных зонах, предназначенных для завершения аренды;
- применение штрафов при нарушении правил парковки (завершении аренды вне специальной зоны);
- ведение информации о зарегистрированных пользователях и состоянии парка самокатов;
- расчёт стоимости аренды и итоговой суммы, подлежащей оплате пользователем за установленный расчётный период, например месяц.

Документ предназначен для заказчика, команды разработки, специалистов по тестированию и сотрудников, отвечающих за эксплуатацию и обслуживание системы.

## Границы применения
Система предназначена для автоматизации процессов предоставления электросамокатов в аренду.

В область применения системы входят:

- **Регистрация пользователей** - создание учётной записи пользователя в мобильном приложении и хранение информации, необходимой для использования сервиса.
- **Идентификация самоката** - определение конкретного самоката посредством сканирования размещённого на нём QR-кода.
- **Просмотр доступности самокатов** - отображение пользователю информации о самокатах, доступных для аренды.
- **Оформление аренды** - выбор самоката пользователем (по правилу: не более 1 самоката на 1 человека) и начало аренды на неопределённый срок через мобильное приложение.
- **Разблокирование самоката** - передача команды аппаратному блоку самоката на снятие блокировки после успешного начала аренды.
- **Контроль состояния самоката** - хранение текущего состояния самоката, включая доступность, аренду, блокировку, исправность и местоположение.
- **Определение местоположения** - получение от самоката GPS-координат посредством SMS-сообщений по запросу центра.
- **Контроль специальных зон** - определение, находится ли самокат в зоне, в которой разрешено завершение аренды без штрафа.
- **Завершение аренды** - завершение поездки пользователем через мобильное приложение с последующей блокировкой самоката.
- **Контроль парковки** - проверка соответствия местоположения самоката требованиям к завершению аренды.
- **Начисление штрафов** - начисление пользователю штрафа при нарушении правил завершения аренды, в частности при оставлении самоката вне разрешённой зоны.
- **Расчёт стоимости аренды** - определение стоимости использования самоката в соответствии с действующими тарифами и фактической продолжительностью аренды.
- **Периодический расчёт задолженности** - определение итоговой суммы, которую пользователь должен оплатить за установленный расчётный период, например за календарный месяц, с учётом стоимости поездок и начисленных штрафов.
- **Управление парком самокатов** - хранение информации о самокатах, их состоянии, местоположении, выводе из эксплуатации при поломке и доступности для аренды.
- **Управление пользователями** - хранение информации о зарегистрированных пользователях и связанных с ними операциях аренды и начислениях.
- **Управление специальными зонами** - хранение информации о парковках и других зонах, в которых разрешено завершение аренды.

В документ не входят:

- разработка конструкции самого электросамоката;
- проектирование и производство GPS-модуля;
- проектирование и производство аппаратного блокиратора;
- проектирование физической инфраструктуры парковок;
- организация сотовой сети и предоставление услуг связи;
- бухгалтерский и налоговый учёт компании;
- управление ремонтными работами над самокатами на уровне производственного процесса;
- непрерывная передача GPS-координат самоката в режиме реального времени, поскольку по условиям системы координаты передаются посредством SMS-сообщений по запросу центра;
- внутреннее устройство программного обеспечения и алгоритмов, за исключением поведения, непосредственно наблюдаемого пользователями и внешними системами.

| **SMS** | Short Message Service - служба обмена короткими текстовыми сообщениями, используемая для передачи информации между самокатом и системой |

| **Специальная зона / ЗЗ** | Территория с идеально точными границами, в которой пользователю разрешено завершить аренду самоката без начисления штрафа |
| **Парковка** | Специальная зона, предназначенная для завершения аренды и оставления самоката |
| **Тариф** | Набор правил и стоимостных параметров, используемых для расчёта стоимости аренды |
| **Штраф** | Денежное начисление пользователю за нарушение правил использования сервиса, в том числе за завершение аренды вне разрешённой зоны |
| **Расчётный период** | Период, за который определяется итоговая сумма начислений пользователя; например, календарный месяц |
| **Итоговая сумма** | Общая сумма денежных начислений пользователя за расчётный период, включающая стоимость аренды и применённые штрафы |

# 2. Общее описание

## Описание изделия
Система представляет собой программно-аппаратный комплекс для предоставления электросамокатов в аренду.

Основными компонентами системы являются:

- **мобильное приложение пользователя**;
- **серверная часть системы (центр)**;
- **база данных пользователей, самокатов, аренд, зон и начислений**;
- **электросамокаты**, оборудованные GPS-модулем, QR-кодом и аппаратным блокиратором;
- **механизм SMS-взаимодействия** между системой и самокатами.

### Интерфейсы системы
Система должна обеспечивать взаимодействие между мобильным приложением, серверной частью и самокатами.

Мобильное приложение передаёт на сервер действия пользователя, включая регистрацию, выбор самоката, начало аренды и завершение аренды.

Серверная часть осуществляет обработку пользовательских действий, хранение данных, расчёт стоимости аренды, контроль зон и управление состоянием самокатов.

Самокат взаимодействует с системой посредством SMS-сообщений. По инициативе центра (сервера) в любое время самокату направляется запрос, после чего GPS-модуль определяет координаты самоката и передаёт их системе посредством ответного SMS. Система также передаёт самокату команды блокировки и разблокирования и ожидает SMS-подтверждения их выполнения.

### Интерфейсы пользователя
**Мобильное приложение пользователя** должно предоставлять возможность:

- регистрации и авторизации;
- просмотра доступных самокатов;
- сканирования QR-кода самоката;
- подтверждения начала аренды;
- получения информации о текущей аренде;
- завершения аренды;
- получения информации о разрешённых зонах завершения аренды;
- просмотра стоимости текущей и завершённых поездок;
- просмотра начисленных штрафов;
- просмотра итоговой суммы за расчётный период и статуса её оплаты.

**Административный интерфейс** предназначен для управления парком самокатов, принудительного опроса координат самокатов, управления пользователями, тарифами, специальными зонами, состояниями самокатов (включая вывод из эксплуатации и возврат в строй) и начислениями.

### Интерфейсы аппаратных средств ЭВМ
Система взаимодействует со следующими аппаратными компонентами:

- **электросамокат** - физическое устройство, предоставляемое пользователю в аренду;
- **GPS-модуль** - определяет координаты самоката без погрешности;
- **аппаратный блокиратор** - обеспечивает физическую блокировку и разблокировку самоката и отправку подтверждения;
- **мобильное устройство пользователя** - обеспечивает работу мобильного приложения;
- **оборудование с поддержкой SMS (SMS-шлюз и GSM-модем самоката)** - обеспечивает обмен сообщениями между системой и модулем самоката.

### Интерфейсы программного обеспечения
Система включает следующие программные компоненты:

- **мобильное приложение** - пользовательский интерфейс сервиса;
- **серверное приложение** - обработка операций и бизнес-логики;
- **база данных** - хранение информации о пользователях, самокатах, арендах, местоположениях, зонах и начислениях;
- **сервис SMS-взаимодействия** - отправка и получение SMS-сообщений;
- **программный интерфейс GPS-модуля и блокиратора самоката** - обеспечение взаимодействия серверной части с аппаратными компонентами самоката.

### Интерфейсы коммуникаций
Основными способами коммуникации являются:

- **мобильный интернет** - обмен данными между мобильным приложением и серверной частью;
- **SMS** - обмен данными между самокатом и системой;
- **GPS** - получение географических координат самокатом.

GPS используется непосредственно для определения координат, а SMS - для передачи полученных координат и управляющей информации между самокатом и системой.

### Ограничения памяти
Конкретные требования к объёму памяти мобильных устройств, серверов и аппаратных компонентов самоката определяются выбранной платформой реализации.

При этом аппаратный модуль самоката должен иметь минимум 64 КБ энергонезависимой памяти для хранения идентификатора самоката, номера сервисного центра и буфера обработки SMS-сообщений.

### Действия
Пользователь выполняет следующие основные действия:

1. Регистрируется в мобильном приложении.
2. Находит доступный самокат.
3. Сканирует QR-код самоката и подтверждает старт в приложении.
4. Сервер отправляет команду разблокировки, самокат подтверждает её и разблокируется.
5. Использует самокат (аренда длится неопределённый срок).
6. Инициирует завершение аренды через мобильное приложение.
7. Система по SMS запрашивает местоположение самоката и отправляет команду блокировки.
8. При подтверждении блокировки система проверяет нахождение самоката в специальной зоне.
9. Если самокат в специальной зоне - аренда завершается по стандартному тарифу.
10. Если самокат вне специальной зоны - аренда завершается и пользователю дополнительно начисляется штраф.

Система также должна обрабатывать специальные ситуации, включая:

- попытку арендовать второй самокат одним пользователем одновременно;
- попытку начать аренду недоступного или неисправного самоката;
- завершение аренды вне разрешённой зоны (начисление штрафа);
- некорректный QR-код;
- отсутствие подтверждения команды блокировки или разблокировки от самоката (пометка самоката как поломанного и вывод из эксплуатации);
- наличие неоплаченной задолженности за прошлый расчётный период.

## Функции изделия
На текущем этапе зафиксированы следующие основные функции системы:

- **Регистрация пользователей** - создание и хранение учётных записей пользователей.
- **Авторизация пользователей** - предоставление доступа зарегистрированным пользователям.
- **Управление профилем пользователя** - хранение информации, связанной с пользователем и его статусом оплаты.
- **Управление парком самокатов** - ведение перечня самокатов и их текущих состояний.
- **Идентификация самоката** - определение самоката по QR-коду.
- **Определение доступности самоката** - проверка, что самокат исправен, свободен, а у пользователя нет другой активной аренды и просроченной задолженности.
- **Начало аренды** - создание операции аренды на неопределённый срок после сканирования QR-кода и подтверждения в приложении.
- **Разблокирование самоката** - снятие аппаратной блокировки после начала аренды с обязательным SMS-подтверждением.
- **Контроль текущей аренды** - хранение информации о пользователе, самокате и времени аренды.
- **Определение местоположения** - получение GPS-координат самоката через SMS по инициативе центра в любое время.
- **Контроль зон** - точное определение нахождения самоката в специальной зоне.
- **Завершение аренды** - завершение аренды пользователем через мобильное приложение.
- **Блокирование самоката** - активация аппаратного блокиратора при завершении аренды с обязательным SMS-подтверждением.
- **Контроль парковки и начисление штрафов** - проверка нахождения самоката в специальной зоне и автоматическое применение штрафа при завершении аренды вне зоны.
- **Расчёт стоимости аренды** - вычисление стоимости поездок в соответствии с тарифом и фактическим временем.
- **Периодический расчёт** - определение общей суммы начислений пользователя за установленный период, включая стоимость аренды и штрафы.
- **Контроль оплаты расчётного периода** - ограничение доступа к новым арендам при неоплате итоговой суммы за расчётный период.
- **Управление тарифами и зонами** - настройка параметров расчёта стоимости аренды и точных границ парковок.
- **Обработка поломок самокатов** - автоматический перевод самоката в статус "Поломан" и вывод из эксплуатации при неподтверждении блокировки или разблокировки.

## Ограничения
На текущем этапе приняты следующие ограничения:

- **Правило одного самоката** - один пользователь может одновременно арендовать только один самокат.
- **Аренда на неопределённый срок** - при старте аренды пользователь не задаёт фиксированное время поездки, аренда длится до момента её завершения в приложении.
- **Определение местоположения посредством GPS и SMS** - координаты запрашиваются по инициативе центра в любое время и передаются посредством SMS.
- **Идеальная точность зон и GPS** - границы специальных зон и координаты GPS считаются абсолютно точными, погрешность измерений принимается равной нулю.
- **Штраф за завершение вне зоны** - пользователь может завершить аренду вне специальной зоны, но при этом система в обязательном порядке начисляет ему штраф.
- **Вывод из эксплуатации при сбое команд** - если самокат не подтвердил разблокировку или блокировку, он автоматически помечается как поломанный и выводится из эксплуатации.
- **Необходимость мобильного приложения** - основные действия пользователя выполняются через мобильное приложение.

# 3. Детальные требования

## Функциональные требования

### 3.1. Управление пользователями и контроль задолженности

- **ФТ-1.1 (Регистрация пользователя)**: Система должна позволять неавторизованному пользователю зарегистрировать учётную запись в мобильном приложении путём ввода ФИО, российского номера мобильного телефона (в формате `+7XXXXXXXXXX`) и подтверждения согласия на обработку персональных данных.
- **ФТ-1.2 (Авторизация)**: Система должна обеспечивать вход зарегистрированного пользователя в мобильное приложение по номеру телефона и коду подтверждения (или паролю).
- **ФТ-1.3 (Проверка активных ограничений пользователя)**: Перед началом новой аренды система должна проверять статус учётной записи пользователя. Пользователь допускается к аренде только при отсутствии текущей активной аренды и отсутствии просроченной задолженности за предыдущие расчётные периоды.

### 3.2. Идентификация самоката и начало аренды

- **ФТ-2.1 (Отображение парка и зон)**: Мобильное приложение должно отображать на карте специальные зоны (парковки) и доступные для аренды самокаты, находящиеся в статусе `Свободен (В эксплуатации)`.
- **ФТ-2.2 (Ограничение "1 человек - 1 самокат")**: Система должна разрешать одному пользователю иметь не более одной активной аренды в любой момент времени. При попытке начать аренду второго самоката при незавершённой текущей аренде система должна отклонить запрос и вывести сообщение об ошибке.
- **ФТ-2.3 (Инициация начала аренды)**: Началом процесса аренды считается последовательное выполнение двух действий пользователем:
  1. Сканирование QR-кода выбранного самоката через мобильное приложение.
  2. Явное подтверждение начала аренды нажатием кнопки "Начать аренду" в мобильном приложении.
- **ФТ-2.4 (Разблокировка самоката при старте)**: После подтверждения начала аренды в приложении серверная часть должна отправить на аппаратный модуль самоката SMS-команду на разблокировку (`UNLOCK`) и ожидать ответного SMS-сообщения от самоката с подтверждением успешного снятия блокировки (`UNLOCK_OK`).
- **ФТ-2.5 (Переход в режим аренды)**: Только после получения от самоката SMS-подтверждения разблокировки система фиксирует фактическое время начала аренды, переводит самокат в статус `В аренде` и открывает сессию аренды на неопределённый срок (без предварительного ограничения по времени).

### 3.3. Определение местоположения и SMS-взаимодействие

- **ФТ-3.1 (Запрос координат по инициативе центра)**: Самокат не должен отправлять координаты самостоятельно по таймеру. Отправка текущих GPS-координат самокатом по SMS должна осуществляться исключительно по инициативе серверного центра в любое время в ответ на входящий SMS-запрос (`GET_LOC`) от сервера.
- **ФТ-3.2 (Случаи запроса координат центром)**: Центр инициирует отправку SMS-запроса координат самокату в следующих случаях:
  - автоматически в момент инициации пользователем завершения аренды в приложении;
  - в любое время по запросу администратора или сотрудника обслуживания через административный интерфейс;
  - по регламентному запросу центральной системы мониторинга.
- **ФТ-3.3 (Точность координат и специальных зон)**: Специальные зоны задаются в системе в виде замкнутых полигонов с идеально точными географическими координатами вершин (широта и долгота). Координаты, получаемые от GPS-модуля самоката, считаются абсолютно точными (погрешность определения местоположения равна $0$ метров). Проверка нахождения самоката в зоне выполняется строгим математическим алгоритмом принадлежности точки многоугольнику без использования буферных зон допуска.

### 3.4. Завершение аренды и контроль специальных зон

- **ФТ-4.1 (Инициация завершения аренды)**: Завершение аренды инициируется арендатором путём нажатия кнопки "Завершить аренду" в мобильном приложении.
- **ФТ-4.2 (Блокировка и опрос координат при завершении)**: При получении запроса на завершение аренды центр отправляет самокату SMS-команду на физическую блокировку и запрос текущих координат (`LOCK_AND_LOC`).
- **ФТ-4.3 (Подтверждение блокировки)**: Самокат активирует аппаратный блокиратор, считывает текущие GPS-координаты и отправляет центру ответное SMS-сообщение с подтверждением блокировки и точными координатами (`LOCK_OK;LAT;LON`).
- **ФТ-4.4 (Завершение аренды внутри специальной зоны)**: Если полученные при завершении аренды координаты самоката находятся внутри границ любой из действующих специальных зон и самокат подтвердил блокировку, аренда успешно закрывается, самокат переводится в статус `Свободен (В эксплуатации)`, а стоимость рассчитывается только за фактическое время пользования.
- **ФТ-4.5 (Завершение аренды вне специальной зоны)**: Если полученные при завершении аренды координаты самоката находятся за пределами всех специальных зон, система не препятствует закрытию аренды: аренда завершается, самокат блокируется и переводится в статус `Свободен (В эксплуатации)`, но пользователю автоматически начисляется фиксированный штраф за оставление самоката вне специальной зоны.

### 3.5. Обработка сбоев блокировки и разблокировки (вывод из эксплуатации)

- **ФТ-5.1 (Неподтверждение разблокировки при старте)**: Если при начале аренды самокат не прислал SMS-подтверждение разблокировки в течение установленного тайм-аута ($60$ секунд) либо прислал сообщение об ошибке (`ERROR`), система автоматически:
  1. Отменяет операцию начала аренды (средства с пользователя не списываются).
  2. Помечает самокат в базе данных как неисправный (устанавливает статус `Поломан / Выведен из эксплуатации`).
  3. Скрывает самокат с карты пользовательского приложения и блокирует возможность сканирования его QR-кода.
  4. Уведомляет пользователя в приложении о технической неисправности самоката и предлагает выбрать другой.
- **ФТ-5.2 (Неподтверждение блокировки при завершении)**: Если при завершении аренды самокат не прислал SMS-подтверждение блокировки в течение установленного тайм-аута ($60$ секунд) либо прислал ошибку, система автоматически:
  1. Прекращает отсчёт оплачиваемого времени аренды для пользователя в момент нажатия им кнопки завершения.
  2. Помечает самокат как неисправный (статус `Поломан / Выведен из эксплуатации`) и исключает его из доступного парка.
  3. Создаёт инцидент в панели сотрудников обслуживания для выезда и проверки самоката.

### 3.6. Расчёт стоимости, расчётный период и работа с неплательщиками

- **ФТ-6.1 (Формула расчёта стоимости поездки)**: Стоимость отдельной завершённой поездки $C_{\text{поездки}}$ рассчитывается в рублях РФ по формуле:
  $$C_{\text{поездки}} = C_{\text{старт}} + (T_{\text{мин}} \times C_{\text{мин}}) + F_{\text{зона}}$$
  где:
  - $C_{\text{старт}}$ - фиксированная стоимость старта аренды по тарифу (руб.);
  - $T_{\text{мин}}$ - фактическая длительность аренды в минутах (округляется в большую сторону до целой минуты);
  - $C_{\text{мин}}$ - стоимость одной минуты аренды по тарифу (руб./мин);
  - $F_{\text{зона}}$ - размер штрафа за завершение аренды вне специальной зоны ($F_{\text{зона}} = 0$, если аренда завершена внутри зоны).
- **ФТ-6.2 (Формирование итоговой суммы за расчётный период)**: В последний день каждого расчётного периода (календарного месяца) система автоматически суммирует стоимость всех поездок и штрафов пользователя за период:
  $$S_{\text{итог}} = \sum_{i=1}^{N} C_{\text{поездки}, i}$$
  Сформированный счёт выставляется пользователю в мобильном приложении со сроком оплаты $5$ календарных дней.
- **ФТ-6.3 (Обработка неоплаченной итоговой суммы)**: Если по истечении установленного срока оплаты (например, до $5$-го числа следующего месяца включительно) итоговая сумма $S_{\text{итог}}$ остаётся неоплаченной, система автоматически выполняет следующие действия:
  1. Переводит учётную запись пользователя в статус `Заблокирован за неуплату`.
  2. Полностью блокирует пользователю возможность начинать новые аренды самокатов до момента полного погашения задолженности.
  3. Отправляет пользователю уведомление о задолженности в мобильном приложении и по SMS.
  4. При просрочке оплаты более чем на $30$ календарных дней включает пользователя в реестр должников в административной панели для передачи данных юридической службе и досудебного взыскания в соответствии с ГК РФ.

### 3.7. Административное управление и обслуживание

- **ФТ-7.1 (Управление специальными зонами и тарифами)**: Администратор должен иметь возможность создавать, редактировать и удалять специальные зоны (задавая точные координаты полигонов), а также изменять параметры тарифов ($C_{\text{старт}}$, $C_{\text{мин}}$, $F_{\text{зона}}$).
- **ФТ-7.2 (Возврат самоката в эксплуатацию)**: Сотрудник обслуживания должен иметь возможность просматривать список самокатов в статусе `Поломан / Выведен из эксплуатации`, и после проведения физического ремонта переводить самокат обратно в рабочий статус `Свободен (В эксплуатации)`.

## Надежность
- **Доступность**: Коэффициент готовности серверной части системы должен составлять не менее $99.5\%$ в режиме $24/7$ в течение сезона проката.
- **MTBF (Средняя наработка на отказ)**: Не менее $1000$ часов непрерывной работы серверного программного обеспечения.
- **MTTR (Среднее время восстановления)**: Не более $30$ минут для серверной части после критического сбоя за счёт автоматического перезапуска контейнеров и резервного копирования БД.
- **Точность**:
  - Точность геопозиционирования и границ специальных зон по условиям проекта принимается абсолютной (погрешность $0$ метров, $100\%$ точность определения вхождения в полигон).
  - Точность финансовых расчётов - до $0.01$ рубля (до одной копейки) без накопления ошибок округления.
- **Макс. количество ошибок**: Не более $1$ необработанного сбоя на $10000$ операций начала/завершения аренды. При потере SMS-ответа от самоката система обязана корректно переводить самокат в статус `Поломан / Выведен из эксплуатации` без зависания пользовательской сессии.

## Производительность
- **Время отклика**:
  - Отклик серверного API на действия в мобильном приложении (просмотр карты, сканирование QR-кода, профиль) - не более $1.5$ секунд при стандартной нагрузке.
  - Время полного цикла разблокировки/блокировки самоката (с учётом времени доставки SMS через сотовую сеть) - в среднем от $5$ до $15$ секунд, максимальный тайм-аут ожидания ответа от самоката - $60$ секунд.
- **Пропускная способность**: Система должна поддерживать одновременную работу до $5000$ активных пользователей и обработку не менее $100$ транзакций (запросов к API и SMS-сообщений) в секунду.
- **Утилизация ресурсов**: При штатной нагрузке загрузка центрального процессора (CPU) и оперативной памяти (RAM) основного сервера не должна превышать $70\%$, утилизация дисковой подсистемы - не более $75\%$.

## Ремонтопригодность
- Серверная часть системы должна разрабатываться по модульному принципу (разделение модулей работы с клиентским API, биллинга, гео-проверки зон и модуля SMS-шлюза), чтобы изменение логики одного модуля не требовало переработки остальных.
- Все операции отправки и получения SMS-сообщений между центром и самокатами, а также смены статусов самокатов должны логироваться в журнал событий с указанием точной временной метки (timestamp) для быстрой диагностики причин вывода самоката из эксплуатации.
- Для аппаратной части предусмотрена автоматическая диагностика по тайм-ауту: любой самокат, не подтвердивший команду блокировки или разблокировки, мгновенно изолируется от пользователей (выводится из эксплуатации) до вмешательства сотрудника обслуживания.

## Ограничения проекта
- **Сроки и команда разработки**: Проект выполняется учебной командой студентов 3 курса университета в рамках семестрового графика в соответствии с учебным планом.
- **Географические и правовые рамки**: Система проектируется для эксплуатации на территории Российской Федерации (расчёты в рублях РФ, поддержка российских операторов связи, соответствие законодательству РФ).
- **Бюджетные и инфраструктурные ограничения**: Для минимизации расходов на передачу данных самокаты не используют постоянное GPRS/LTE-соединение, весь обмен телеметрией и командами с самокатами строго ограничен протоколом SMS.
- **Учебные допущения**: В рамках проекта аппаратный самокат и SMS-шлюз могут быть реализованы в виде программного эмулятора (заглушки), имитирующего ответы GPS-модуля и блокиратора, включая сценарии отказа (неподтверждения команд).

## Требования к пользовательской документации
В состав пользовательской и сопроводительной документации (на русском языке) должны входить:
- **Руководство пользователя мобильного приложения** (встроенная справка в приложении): правила сканирования QR-кода, правило "1 человек - 1 самокат", правила парковки в специальных зонах, условия начисления штрафов и порядок оплаты счетов за расчётный период.
- **Руководство администратора и сотрудника обслуживания**: инструкция по работе с веб-панелью, принудительному SMS-опросу координат, настройке полигонов специальных зон, работе со списком должников и возврату поломанных самокатов в эксплуатацию.

## Используемые компоненты
Для реализации системы используются следующие программные и аппаратные компоненты:
- **СУБД**: PostgreSQL (с расширением PostGIS или встроенным модулем геометрических вычислений для точной проверки координат).
- **Картографический сервис**: Яндекс Карты API или OpenStreetMap (для отображения карты города, специальных зон и самокатов в мобильном приложении и веб-панели).
- **Сервис SMS-коммуникаций**: Программный SMS-шлюз (по протоколу SMPP или HTTP API российских агрегаторов) либо программный эмулятор SMS-центра для тестирования.
- **Аппаратные компоненты самоката** (в реальной среде): микроконтроллер с GSM-модулем приёма/передачи SMS, GPS/ГЛОНАСС-приёмник и электромеханический блокиратор колеса.

## Интерфейсы
- **Интерфейс пользователя (UI)**:
  - *Мобильное приложение (iOS / Android)*: экран авторизации, интерактивная карта со специальными зонами и доступными самокатами, экран сканера QR-кода (через камеру смартфона), экран подтверждения и управления текущей арендой (с таймером и текущей стоимостью), экран истории поездок, штрафов и оплаты счёта за расчётный период.
  - *Веб-интерфейс администратора и сотрудника обслуживания*: таблица и карта парка самокатов (с кнопкой принудительного запроса координат по SMS и фильтром поломанных самокатов), редактор полигонов специальных зон, справочник тарифов, реестр пользователей и должников.
- **Аппаратные интерфейсы**:
  - Взаимодействие микроконтроллера самоката с GPS-приёмником и GSM-модемом осуществляется по последовательному интерфейсу UART.
  - Управление аппаратным блокиратором осуществляется через цифровой управляющий выход микроконтроллера (GPIO) с датчиком обратной связи (концевым выключателем) для проверки фактического срабатывания замка перед отправкой подтверждения.
- **Программные интерфейсы (API)**:
  - Взаимодействие мобильного приложения и административной веб-панели с серверной частью осуществляется по протоколу HTTPS (REST API, формат обмена данными - JSON).
  - Взаимодействие серверной части с SMS-шлюзом осуществляется через REST API (Webhook для входящих SMS от самокатов и POST-запросы для отправки команд от центра).
- **Интерфейсы коммуникаций**:
  - Канал "Мобильное приложение - Сервер": беспроводная передача данных по сетям мобильной связи (3G/4G/5G) или Wi-Fi по протоколу HTTPS (TLS 1.2/1.3).
  - Канал "Сервер (Центр) - Самокат": обмен короткими текстовыми сообщениями (SMS) по сетям сотовой связи стандарта GSM. Формат сообщений - текстовый, структурированный разделителями (например, `CMD:LOCK_AND_LOC;ID:1045`).

## Требования лицензирования
- Разрабатываемое серверное, веб- и мобильное программное обеспечение должно создаваться с использованием свободно распространяемых компонентов и библиотек с открытым исходным кодом (лицензии MIT, Apache 2.0, BSD, PostgreSQL License).
- Исключительные права на разработанный программный код принадлежат авторам проекта (учебной команде разработки).
- При использовании сторонних картографических сервисов (например, API Яндекс Карт) соблюдаются условия бесплатного некоммерческого/учебного тарифа.

Разработка документации и программного обеспечения ведётся с учётом следующих стандартов и нормативных актов:
