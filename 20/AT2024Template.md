# 1. Введение
Спецификация определяет, как сотрудники холдинга учитывают лицензии на ПО, распределяют права использования и отслеживают сроки действия. Раздел 3 описывает ожидаемые результаты операций и условия их проверки.

## Цели
Формирование требований к системе учета программных лицензий (СУПЛ) на основе стандарта IEEE Std 830-1998 для согласования архитектуры, функциональности и правил приемки программного продукта между разработчиками, тестировщиками и заказчиком, а также обеспечение контроля соответствия между закупленными лицензиями и фактически установленным программным обеспечением на основе интеграции с внешними системами инвентаризации.

## Границы применения
Система предназначена для централизованного учета программных и аппаратных лицензий на предприятии со структурой холдинга.

**Функциональные границы:**
* Ведение единого реестра лицензий ПО с привязкой к юридическим лицам холдинга, контрагентам-продавцам и компаниям-правообладателям.
* Фиксация параметров лицензий: название ПО, срок действия (ограниченный или бессрочный), объем (количество копий), форма ключа (программный код или аппаратный USB-носитель).
* Разделение схем лицензирования: привязка к конечному устройству либо конкурентный (сетевой) доступ для пула сотрудников с учетом разрешенного числа одновременных рабочих мест.
* Формирование отчетов по текущим активным лицензиям и лицензиям с истекающим сроком действия (с возможностью задания периода предупреждения в 2, 3 и 6 месяцев).
* Сохранение и просмотр просроченных лицензий.
* Уведомления о приближении срока окончания лицензий.
* Интеграция с внешними системами инвентаризации: получение реестров устройств (компьютеров, серверов), списков пользователей и перечней установленного на устройствах ПО.
* Ведение справочника правил сопоставления (нормализации) наименований установленного ПО с закупленными лицензиями.
* Автоматический расчет лицензионного баланса: выявление нехватки лицензий (дефицита / недолицензирования) и их избытка (профицита / перелицензирования).
* Формирование и выгрузка отчета о лицензионном соответствии (комплаенс-отчета) по закупленным лицензиям и фактически обнаруженным установкам.

**Вне границ системы:**
* Система не выполняет функции сервера сетевых лицензий (License Manager) и не блокирует запуск сторонних программ на уровне операционной системы.
* Система не ведет бухгалтерские проводки и финансовые расчеты.
* Система не осуществляет прямое сканирование рабочих станций (не содержит резидентных агентов) и получает инвентарные данные исключительно через интерфейсы внешних систем (SCCM, GLPI, Active Directory и др.).
* Система не производит автоматическое принудительное удаление нелицензионного ПО с рабочих станций.

## Термины и аббревиатуры

| Обозначение | Определение |
|-------------|-------------|
| **СУПЛ (SAM)** | Система учета программных лицензий (Software Asset Management). |
| **Юрлицо холдинга** | Организация в составе холдинга, на баланс которой оформлена лицензия. |
| **Правообладатель** | Компания-разработчик софта, владеющая авторскими правами (например, ООО "1С"). |
| **Контрагент** | Партнер, дистрибьютор или франчайзи, у которого приобретена лицензия. |
| **Программная лицензия** | Лицензия, активируемая цифровым ключом или кодом активации. |
| **Аппаратная лицензия** | Лицензия, поставляемая на физическом электронном носителе (USB-токен). |
| **Лицензия на устройство** | Модель лицензирования с привязкой к конкретному компьютеру или серверу. |
| **Конкурентная лицензия** | Модель лицензирования, допускающая одновременную работу фиксированного числа пользователей из утвержденного списка. |
| **Срочная лицензия** | Лицензия с установленной датой окончания действия. |
| **Бессрочная лицензия** | Лицензия без даты окончания действия. |
| **Активная лицензия** | Несписанная бессрочная лицензия либо несписанная срочная лицензия, дата окончания которой не раньше текущей даты. |
| **Просроченная лицензия** | Несписанная срочная лицензия, дата окончания которой раньше текущей даты. |
| **Период предупреждения** | Временной интервал (2, 3 или 6 месяцев) для фильтрации истекающих лицензий и формирования уведомлений. |
| **Внешняя система инвентаризации** | Внешний программный комплекс учета ИТ-активов и каталогов (SCCM, GLPI, Active Directory и др.), содержащий актуальные данные об устройствах, пользователях и установленном ПО. |
| **Установленное ПО** | Программный продукт, фактически обнаруженный на рабочей станции или сервере внешней системой инвентаризации. |
| **Справочник сопоставления ПО** | Таблица правил нормализации, устанавливающая соответствие между исходным строковым наименованием установленного ПО из внешней системы и закупленной лицензией холдинга. |
| **Лицензионный комплаенс** | Степень соответствия между количеством фактически установленных экземпляров ПО и количеством приобретенных действующих лицензий. |
| **Дефицит лицензий** | Состояние, при котором количество фактически установленных копий ПО превышает количество закупленных активных лицензий (риск юридической ответственности и санкций). |
| **Профицит лицензий** | Состояние, при котором количество закупленных активных лицензий превышает количество реально установленных копий ПО (избыточные финансовые затраты). |

# 2. Общее описание

## Описание изделия
СУПЛ представляет собой централизованное веб-приложение, предназначенное для работы во внутренней сети предприятия.

- **Интерфейсы системы**: клиент-серверная архитектура: веб-клиент, сервер приложений и реляционная база данных.
- **Интерфейсы пользователя**: доступ через стандартный веб-браузер (Google Chrome, Firefox, Edge, Яндекс.Браузер). Графический интерфейс включает экранные формы карточек лицензий, таблицы реестров с фильтрацией, интерфейсы правил нормализации ПО и экраны генерации аналитических отчетов.
- **Интерфейсы аппаратных средств ЭВМ**: стандартные рабочие места пользователей (монитор, клавиатура, мышь). Взаимодействие с аппаратными USB-ключами ограничивается ручным учетом их реквизитов (серийный номер, ответственное лицо).
- **Интерфейсы программного обеспечения**: взаимодействие с реляционной СУБД (PostgreSQL / MySQL). Интеграция с внешними системами инвентаризации и службами каталогов (SCCM, GLPI, Active Directory) через REST API и LDAP для автоматизированной загрузки устройств, пользователей и перечня установленного ПО. Возможность выгрузки отчетов в форматы XLSX, CSV и PDF.
- **Интерфейсы коммуникаций**: взаимодействие компонентов системы и доступ к базе данных по локальной сети через стек протоколов TCP/IP. Защищенный сетевой обмен с внешними системами инвентаризации по протоколам HTTPS и LDAPS.
- **Ограничения памяти**: потребление оперативной памяти клиентским веб-приложением в браузере - не более 250 МБ. Объем дискового пространства сервера под базу данных - от 2 ГБ для учета до 10 000 записей.
- **Действия**: интерактивная работа пользователей, автоматическое ежедневное фоновое задание по проверке сроков действия лицензий и формированию оповещений, а также регламентная и ручная синхронизация инвентарных данных с внешними системами с расчетом лицензионного баланса.

## Функции изделия
1. **Ведение справочников:** учет юридических лиц холдинга, компаний-правообладателей, контрагентов-поставщиков, оборудования, сотрудников, а также справочника правил сопоставления (нормализации) наименований установленного ПО с лицензиями.
2. **Учет лицензий:** создание, просмотр, редактирование и списание карточек лицензий со всеми атрибутами (название ПО, юрлицо-владелец, контрагент, правообладатель, признак срочной или бессрочной лицензии, срок окончания для срочной лицензии, число копий, тип ключа, модель лицензирования). Просроченные лицензии сохраняются и доступны для просмотра.
3. **Распределение прав использования:**
   * Назначение лицензий "на устройство" на конкретные рабочие станции.
   * Назначение конкурентных лицензий на утвержденный список сотрудников с фиксацией лимита одновременных рабочих мест.
4. **Формирование отчетов:**
   * Отчет по активным лицензиям на текущую дату.
   * Отчет по лицензиям с истекающим сроком действия с периодом предупреждения в 2, 3 или 6 месяцев.
   * Отчет о лицензионном соответствии (комплаенс-отчет): сопоставление закупленных лицензий и фактически установленного ПО с отражением дефицита и профицита.
5. **Уведомления:** оповещение о приближении срока окончания срочных лицензий в выбранный период предупреждения.
6. **Интеграция с внешними системами:** импорт перечня устройств (компьютеров, серверов), списков пользователей, а также опрос внешних систем для получения перечня фактически установленного программного обеспечения по выбранному устройству или в рамках пакетного запроса.
7. **Контроль лицензионного соответствия:** сопоставление фактических установок ПО с действующими лицензиями на основе правил справочника нормализации, автоматическое определение нехватки лицензий (дефицита / недолицензирования) или их избытка (профицита / перелицензирования).

## Характеристики пользователей
* **Системный администратор**: настройка системы, управление учетными записями и правами доступа, ведение общесистемных справочников, настройка параметров сетевого подключения и расписания синхронизации с внешними системами инвентаризации.
* **Специалист по закупкам / SAM-менеджер**: внесение договоров и карточек лицензий, распределение лицензий по пользователям и ПК, контроль сроков окончания, ведение правил сопоставления наименований ПО с лицензиями, запуск инвентаризации по устройствам, контроль дефицита и профицита лицензий, формирование аналитических отчетов.
* **Руководитель IT**: просмотр сводной аналитики, мониторинг рисков просрочки лицензий, контроль лицензионного соответствия (минимизация рисков юридической ответственности при дефиците и оптимизация затрат холдинга при профиците).

## Ограничения
* Доступ к данным и операциям разграничивается на основе ролевой модели доступа (RBAC).
* Серверная часть должна развертываться в среде ОС Linux.
* Персональные данные сотрудников защищаются согласно требованиям информационной безопасности предприятия.

## Предположения и зависимости
* Внесение данных о закупках и изменениях лицензий выполняется ответственными сотрудниками без задержек.
* На сервере настроена синхронизация системного времени по протоколу NTP для корректного расчета сроков истечения лицензий.
* Внешние системы инвентаризации (SCCM, GLPI, Active Directory) функционируют штатно и содержат достоверные данные об устройствах холдинга, пользователях и установленном программном обеспечении.

# 3. Детальные требования

## Функциональные требования

Операции доступны после входа в систему (ФТ-15) и проверки прав (ФТ-16). В карточке обязательны название ПО, юридическое лицо - владелец лицензии, продавец, правообладатель, количество копий (положительное целое число), тип и реквизиты ключа, модель лицензирования и признак "Срочная" или "Бессрочная". Для программного ключа указывается ключ или код активации, для аппаратного - серийный номер USB-носителя и ответственное лицо. Юридическое лицо, продавец, правообладатель и ответственное лицо выбираются из справочников.
### Учет и просмотр лицензий

#### ФТ-01. Создание срочной лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-01 |
| Название | Создание срочной лицензии |
| Описание | Система должна позволять создавать карточку лицензии с ограниченным сроком действия. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Связанные записи внесены в справочники. |
| Входные данные | Общие обязательные поля карточки, признак "Срочная" и дата окончания действия. |
| Результат | Карточка сохранена с уникальным идентификатором. Если дата окончания раньше текущей даты сервера, лицензия отображается как просроченная; иначе - как активная. |
| Обработка ошибок | При незаполненных обязательных полях, неверной дате или некорректном количестве копий сохранение отклоняется; система указывает поля, требующие исправления. |

#### ФТ-02. Создание бессрочной лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-02 |
| Название | Создание бессрочной лицензии |
| Описание | Система должна позволять создавать карточку лицензии без ограничения срока действия. |
| Исполнитель | SAM-менеджер. |
| Предусловия | Связанные записи внесены в справочники. |
| Входные данные | Общие обязательные поля карточки и признак "Бессрочная". |
| Результат | Карточка сохранена с уникальным идентификатором и без даты окончания. Лицензия считается активной до списания. Поле даты окончания недоступно для заполнения. |
| Обработка ошибок | При незаполненных обязательных полях или некорректном количестве копий сохранение отклоняется; система указывает поля, требующие исправления. |

#### ФТ-03. Просмотр и изменение карточки лицензии

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-03 |
| Название | Просмотр и изменение карточки лицензии |
| Описание | Система должна позволять просматривать полные сведения о выбранной лицензии и изменять данные ее карточки в соответствии с правами пользователя. |
| Исполнитель | SAM-менеджер - просмотр и изменение; руководитель IT - только просмотр. |
| Предусловия | Карточка лицензии существует. Изменение допускается только для несписанной карточки. |
| Входные данные | Идентификатор лицензии и выбранная операция: просмотр или изменение. При изменении - новые значения полей карточки. |

Для конкурентной лицензии отображаются список сотрудников и лимит одновременных рабочих мест. Просроченные и списанные карточки доступны для просмотра. При изменении данные сохраняются с учетом обязательных полей и правил ФТ-01 или ФТ-02; идентификатор карточки сохраняется. При переходе к бессрочной лицензии дата окончания удаляется. |
| Обработка ошибок | Если карточка не найдена, система показывает сообщение "Лицензия не найдена". При изменении отклоняются неверные данные, уменьшение числа копий ниже числа назначенных устройств или установленного конкурентного лимита, а также смена модели лицензирования при наличии назначений. Изменение списанной карточки или изменение руководителем IT отклоняется. Причина отказа отображается, прежние данные сохраняются. |

#### ФТ-21. Анализ дефицита и профицита лицензий

| Атрибут | Значение |
|---|---|
| Идентификатор | ФТ-21 |
| Название | Анализ дефицита и профицита лицензий |
| Описание | Система должна рассчитывать лицензионный баланс путем сопоставления числа приобретенных активных лицензий с количеством фактически установленных экземпляров сопоставленного ПО на устройствах холдинга с определением дефицита или профицита. |
| Исполнитель | SAM-менеджер, руководитель IT (интерактивный запуск), система (ежедневный фоновый расчет). |
| Предусловия | Загружены данные об установленном ПО (ФТ-19), заполнен справочник сопоставления (ФТ-20), в реестре присутствуют активные лицензии. |
| Входные данные | Запрос на проведение анализа, опциональные фильтры по юрлицу холдинга, правообладателю или группе ПО. |
| Результат | Для каждого программного продукта рассчитываются: общее количество приобретенных активных копий лицензий ($N_{lic}$), количество фактически обнаруженных установок ($N_{inst}$) и разность $\Delta = N_{lic} - N_{inst}$. При $\Delta < 0$ фиксируется дефицит (недолицензирование) с указанием объема нехватки $|\Delta|$ (риск санкций). При $\Delta > 0$ фиксируется профицит (перелицензирование) с указанием неиспользуемого запаса $\Delta$ (потенциал оптимизации затрат). При $\Delta = 0$ фиксируется точное соответствие. |
| Обработка ошибок | Если обнаруженное ПО не связано ни с одной лицензией в справочнике сопоставления, оно помечается как "ПО без лицензии / требует сопоставления" и выводится в отдельный список предупреждений без блокировки общего расчета. |

| Описание | Система должна формировать сводный аналитический отчет о лицензионном соответствии (комплаенс-отчет), сопоставляющий закупленные лицензии и реально установленные копии ПО с детальной расшифровкой дефицита и профицита. |
| Исполнитель | SAM-менеджер, руководитель IT. |
| Предусловия | Пользователь открыл раздел отчетов; расчет баланса выполнен (ФТ-21). |
| Входные данные | Параметры фильтрации: юридическое лицо холдинга, правообладатель, статус баланса ("Все", "Только дефицит", "Только профицит", "Точное соответствие"). |

Отчет доступен для выгрузки в файл по ФТ-11. |
| Обработка ошибок | При отсутствии данных по выбранным фильтрам отображается пустая таблица с сообщением "Записи не найдены". При сбое генерации отчета система информирует пользователя о невозможности построения отчета. |

## Надежность

- Система должна подтверждать сохранение карточки или назначения только после записи всех изменений. Если запись прервана, после перезапуска пользователю доступны либо прежние данные, либо полностью сохраненный результат.
- Если два SAM-менеджера одновременно назначают последнюю свободную копию разным устройствам, система должна сохранить только одно назначение. Второй пользователь получает сообщение "Нет свободных копий" (ФТ-06).
- После восстановления базы из резервной копии карточки, назначения, роли и настройки должны соответствовать состоянию на момент создания копии. Для проверки администратор сверяет число записей и список устройств у контрольной лицензии до копирования и после восстановления.
- При сбое соединения с внешней системой инвентаризации в процессе импорта устройств, пользователей или списка ПО система должна откатывать текущую пакетную транзакцию. Данные справочников сохраняются в согласованном состоянии, частичные или поврежденные записи не сохраняются.
- При временной недоступности внешней системы инвентаризации СУПЛ сохраняет последние успешно полученные инвентарные данные, фиксирует дату их актуальности и повторяет попытку синхронизации при следующем регламентном запуске.

## Производительность

Испытание проводят в локальной сети предприятия на реестре из 10 000 лицензий и базе до 5 000 устройств. Время измеряют в браузере от нажатия кнопки до отображения результата. Значения в таблице предложены для обсуждения. Для приемки применяются пределы, согласованные с заказчиком до начала испытаний.

| Операция | Предлагаемое время, требует согласования |
|---|---|
| Открыть карточку по идентификатору (ФТ-03) | 3 секунды |
| Отфильтровать реестр по юридическому лицу и состоянию (ФТ-05) | 3 секунды |
| Сформировать и показать отчет по активным или истекающим лицензиям (ФТ-09, ФТ-10) | 10 секунд |

| Выполнить пакетный запрос установленного ПО по всем устройствам (до 5000 устройств) (ФТ-19) | 120 секунд (фоновый процесс) |

## Ремонтопригодность

При сбое ежедневной проверки сроков система должна записать в журнал время запуска, результат и причину ошибки. По журналу администратор должен иметь возможность отличить успешную проверку без истекающих лицензий от проверки, завершившейся с ошибкой. В журнал событий также должны протоколироваться результаты каждого сеанса синхронизации с внешними системами инвентаризации (время запуска, длительность, число импортированных объектов, перечень нераспознанных названий ПО). Порядок просмотра журнала и восстановления базы должен быть описан в руководстве администратора.

## Ограничения проекта

Серверная часть работает под Linux во внутренней сети предприятия. Даты для отчетов и уведомлений определяются по часам сервера. СУПЛ учитывает назначения и разрешенный лимит конкурентной лицензии. Контроль фактических сеансов и блокировка запуска программ находятся за границами проекта. Сбор сведений об установленном ПО выполняется исключительно путем обращения к API или базам данных внешних систем управления активами (SCCM, GLPI и др.); разработка и установка собственных резидентных агентов сканирования на рабочие станции холдинга исключается.

## Используемые компоненты

Браузер отображает реестр, карточки, отчеты и интерфейсы настройки правил сопоставления ПО. Сервер приложений проверяет права, выполняет операции с лицензиями, производит опрос внешних систем инвентаризации, рассчитывает баланс лицензий и запускает регламентные фоновые задания. Реляционная СУБД (PostgreSQL или MySQL) хранит справочники, карточки, назначения, учетные записи, роли, настройки уведомлений, реестры импортированных устройств, пользователей, записей установленного ПО и правила сопоставления.
